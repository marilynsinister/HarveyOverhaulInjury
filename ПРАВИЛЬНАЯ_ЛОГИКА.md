# ✅ Правильная логика работы (ФИНАЛЬНАЯ ВЕРСИЯ)

## 🎯 Основной принцип

**Харви должен ЗАМЕТИТЬ раны, чтобы начать госпитализацию!**

Не автоматическая телепортация при входе в локацию, а:
- **Proximity Detection** - Харви рядом
- **Обнаружение** - Харви замечает критические травмы
- **Реакция** - Принудительная госпитализация

### Сценарий 3: Событие с Харви → Госпитализация после

```
Любое событие с Харви (например, в клинике)
   ↓

   ↓

   ↓

   ↓

   ↓

   ↓
CheckHarveyProximity() снова активна:
   • Харви рядом? ✅
   • Критические травмы остались? ✅
   ↓
⚠️ ГОСПИТАЛИЗАЦИЯ после события!
```

## 🔧 Как это работает в коде

### 1. CheckHarveyProximity() - Главная логика

```csharp
private void CheckHarveyProximity()
{
    if (!Context.IsPlayerFree) return; // Не во время событий/диалогов
    
    var harvey = HarveyHelper.FindHarveyInLocation(Game1.currentLocation);
    if (harvey == null) return; // Харви нет рядом
    
    float distance = CalculateDistance(Game1.player, harvey);
    
    if (distance <= _config.ProximityTiles) // 3-5 клеток
    {
        var injuries = _injuryManager.CollectAllInjuries();
        
        // ПРИОРИТЕТ 1: Критические травмы → госпитализация
        if (HasCriticalInjuries && !IsAlreadyHospitalized)
        {
            _hospitalizationManager.StartForcedHospitalization(injury, harvey);
            return;
        }
        
        // ПРИОРИТЕТ 2: Обычные травмы → просто реакция
        if (!_proximityReactionShown)
        {
            ShowProximityDiscovery(harvey, injuries);
            _proximityReactionShown = true;
        }
    }
}
```

**Вызывается:** Каждые 60 тиков (~1 секунда) в UpdateTicked

### 2. PassOutHandler - Обморок в шахте

```csharp
public void OnPlayerWarped()
{
    bool wasInMine = LastPassedOutLocation.Contains("Mine");
    
    if (wasInMine && критическое_здоровье)
    {
        // НЕ применяем травму сразу!
        // Только добавляем топик для события
        _dialogueManager.AddTopic("topicMineDeathRescue", 1);
    }
}
```

**Результат:** Событие на следующий день, травмы остаются

---

### 3. События НЕ убирают критические баффы

**Было (неправильно):**
```json
"action RemoveBuff buffBadlyHurt/"  ← УДАЛЯЛО травму!
```

**Стало (правильно):**
```json
// НЕТ команды RemoveBuff!
// Травмы остаются → Харви замечает → Госпитализация
```

## 📊 Таблица срабатывания

| Условие | CheckHarveyProximity | Госпитализация | События |
|---------|---------------------|----------------|---------|
| **Харви рядом + критические травмы** | ✅ Срабатывает | ✅ Да | ❌ Нет |
| **Событие идёт (eventUp)** | ❌ Не срабатывает | ⏸️ Отложена | ✅ Идёт |
| **После события + травмы** | ✅ Срабатывает | ✅ Да | ✅ Закончилось |
| **Харви далеко (>5 клеток)** | ❌ Не срабатывает | ❌ Нет | н/д |
| **Обычные травмы (не критические)** | ✅ Реакция | ❌ Нет | ❌ Нет |

## ✅ Преимущества новой логики

1. **Реалистичность:** Харви должен ВИДЕТЬ раны
2. **Гибкость:** Работает в любой локации где есть Харви
3. **Нет конфликтов:** Не прерывает события
4. **Естественность:** Proximity detection уже существовала
5. **Расширяемость:** Легко добавить новые локации

## 🎯 Ключевые отличия

| Старая логика (неправильная) | Новая логика (правильная) |
|------------------------------|---------------------------|
| Автоматическая госпитализация при входе в Mine | Только если Харви РЯДОМ и ВИДИТ |
| Событие убирало травмы | Событие оставляет травмы |
| Госпитализация в Mine | Госпитализация в Hospital |
| Только в шахтах | В любой локации где есть Харви |

## 🎉 ИТОГ

**Теперь всё логично:**
- Обморок → Событие на след. день (флэшбэк)
- Травмы остаются после события
- Харви замечает → Госпитализация
- Интерактивное лечение
- Автоматическая выписка

**Ничего не пропускается, всё естественно!** ✅
