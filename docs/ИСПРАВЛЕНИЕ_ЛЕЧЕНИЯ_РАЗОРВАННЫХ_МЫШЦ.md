# 🔧 Исправление: лечение разорванных мышц не начинается

## 📋 Проблема

**Симптом:** У игрока есть дебафф `buffTornMuscles`, но при разговоре с Харви лечение не начинается.

## 🔍 Анализ

### Причина проблемы

В файле `EventHandlers/InteractionHandler.cs` на строке **97** была ошибка в логике определения основной травмы:

```csharp
// СТАРЫЙ КОД (НЕПРАВИЛЬНЫЙ)
string? mainInjury = modDebuffs
    .Where(d => _buffManager.HasBuff(d.BuffId))  // ← ПРОБЛЕМА!
    .OrderByDescending(d => GetInjuryPriority(d.BuffId))
    .FirstOrDefault()?.BuffId;
```

**Что происходило:**

1. Игрок получает травму `buffTornMuscles`
2. Создается `DebuffState` с `TreatmentStarted = false`, `CurrentPhase = 0`
3. Применяется бафф `buffTornMuscles` на целый день (`-2`)
4. **Бафф истекает в конце дня** или удаляется по другой причине
5. `DebuffState` остается активным (что правильно для фазовых травм)
6. При разговоре с Харви:
   - `modDebuffs` содержит `buffTornMuscles` (из `StateManager`)
   - Но `_buffManager.HasBuff("buffTornMuscles")` возвращает `false` (бафф истёк)
   - Фильтр `.Where(d => _buffManager.HasBuff(d.BuffId))` исключает травму
   - `mainInjury = null`
   - Лечение не начинается

### Логика системы

Для **фазовых травм** (таких как `buffTornMuscles`, `buffConcussion`, `buffFracturedBone`):

- **Базовый бафф** (`buffTornMuscles`) - это только маркер нелеченной травмы
- **Фазовые баффы** (`HarveyMod_TornMuscles_Acute`, `HarveyMod_TornMuscles_Healing`, `HarveyMod_TornMuscles_Rehab`) - это баффы лечения
- **`DebuffState`** - это источник истины о наличии травмы
- Базовый бафф может истечь, но `DebuffState` остаётся активным до завершения лечения

## ✅ Решение

### Изменения в коде

**Файл:** `EventHandlers/InteractionHandler.cs`, строки 95-108

```csharp
// НОВЫЙ КОД (ПРАВИЛЬНЫЙ)
string? mainInjury = modDebuffs
    .Where(d => 
    {
        // Если лечение уже началось (фазовая травма), не требуем наличия базового баффа
        if (d.TreatmentStarted)
            return true;
        
        // Для нелеченных травм проверяем наличие баффа
        return _buffManager.HasBuff(d.BuffId);
    })
    .OrderByDescending(d => GetInjuryPriority(d.BuffId))
    .FirstOrDefault()?.BuffId;
```

### Логика исправления

1. **Если `TreatmentStarted = true`** (лечение уже началось):
   - Травма учитывается **независимо** от наличия базового баффа
   - Это важно для фазовых травм в процессе лечения

2. **Если `TreatmentStarted = false`** (лечение ещё не началось):
   - Проверяем наличие базового баффа
   - Это защищает от устаревших `DebuffState`

### Дополнительное логирование

Добавлено детальное логирование для отладки (строки 82-88):

```csharp
foreach (var debuff in modDebuffs)
{
    bool hasBuff = _buffManager.HasBuff(debuff.BuffId);
    _monitor.Log($"  - {debuff.BuffId}: TreatmentStarted={debuff.TreatmentStarted}, HasBuff={hasBuff}, Phase={debuff.CurrentPhase}", LogLevel.Debug);
}
```

Это позволяет видеть в логах:
- Какие дебаффы обнаружены
- Начато ли лечение
- Есть ли активный бафф
- На какой фазе находится травма

   - `TreatmentStarted = false`, `HasBuff = true`
   - Травма обнаружена ✅
   - Лечение начинается ✅

2. **Сценарий 2:** Игрок получил травму, бафф истёк

   - Это правильное поведение - защита от багов

3. **Сценарий 3:** Лечение началось, находится в фазе
   - `TreatmentStarted = true`, `HasBuff = false` (базовый бафф не нужен)
   - Травма обнаружена ✅
   - Продолжение лечения ✅
